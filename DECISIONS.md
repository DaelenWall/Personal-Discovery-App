# Implementation decisions

- The specification is the product source of truth. This is a single-user app with no accounts or telemetry. Desktop run scripts bind to localhost; the private beta explicitly opts into a paired HTTPS service on the Mac's private network address.
- Use Next.js App Router, strict TypeScript, Tailwind, and Node 24's built-in SQLite driver. A small typed repository stores each domain object in its own table, with JSON payloads and transaction boundaries. This avoids an ORM and native driver installation for a small local dataset. Node 24 or newer is required.
- Rank a finite, deterministic batch once at session creation. Refresh resumes that batch. Known and dismissed ideas are excluded; previously seen ideas receive a novelty penalty. A time session also has a finite maximum batch of 15 ideas.
- The clock contract measures elapsed wall time, including time away. Dwell measures visible reading time only. Timestamps and capped elapsed intervals prevent counting background time as reading. The Mac supplies desktop timestamps; the device supplies timestamps for its own offline data.
- Enough starts conservatively: ten consecutive fast cards (eight in balanced mode) plus a low rolling median and no meaningful action in that run. A separate long passive run also requires rapid reading. Time expiry alone does not trigger Enough.
- Explicit extensions are the only operation permitted to add a fresh finite batch. Extensions record events and reset the Enough observation window; they never silently refresh a feed.
- Demo explanations are original editorial paraphrases, labeled as such. Source metadata points to supporting originals or reputable references; seed raw text is an editorial source note, not a claimed quotation.
- Recall is optional, offered after five substantive ideas, and never blocks ending a session. Multiple-choice recall works offline; free-text demo evaluation is approximate and labeled.
- An API key and centrally configured model enable optional AI. Without either, demo Ask uses stored explanations and explicitly describes its limits; ingestion drafts use source extracts without pretending to generate new claims.
- Keep the local web server private. Same-origin mutation checks and safe public URL extraction protect the local store without adding account infrastructure.
- Pin TypeScript 6 for parser compatibility. Use current ESLint with TypeScript and React Hooks rules directly; the Next.js lint bundle currently has incompatible React rules and an unpatched transitive dependency. Use Webpack because Turbopack's CSS worker cannot bind its required port in this execution environment. Disable Next.js telemetry in run scripts.
- Ingestion previews live in a bounded server-memory cache for 30 minutes and expire on restart. Only reviewed sources and ideas enter SQLite. Unknown sources begin with a conservative quality estimate; extract verification does not establish semantic truth.
- Actions taken outside a reading session use a `library` event scope. Repeated questions, deep dives, and source opens are retained as events; preference learning applies once per idea/action/scope to avoid overfitting repeat clicks.
- User update, October 6: a time budget is a reminder, not an interruption. The current idea, its deep dive, source, Ask, notes, and pending recall remain available after the deadline. The feed's Next action ends the session without revealing a new idea. Known/dismiss actions on the feed also advance and therefore end an expired session. Actual visible dwell continues after the deadline. Card budgets retain their finite endings.
- Reminder dismissal persists for the current session segment, including refresh and navigation into depth. An explicit extension resets it. Recall completed after expiry stays in place until Next; it never reveals the queued idea automatically.
- Real Ask uses OpenAI after the user supplies a key and model in Settings or environment variables. In-app credentials live in a separate, owner-readable file beside the SQLite database (mode 0600), never in browser responses, reading exports, or version control. Local setup takes precedence over environment configuration and takes effect immediately. Reading-data reset retains provider credentials.
- User update, October 6: adapt for a private iPhone **beta**, with no public distribution. Use a Safari Home Screen PWA as the conservative installation route: it requires no developer account, signing renewal, or Xcode (full Xcode is not installed here). A native wrapper is deferred until a concrete native capability is needed.
- `/phone` bundles the existing screens and domain engine in one shell with hash navigation, so offline routing requires no server rendering. Device reading data is committed atomically to IndexedDB. First opening copies Mac reading data once; thereafter the collections are independent. There is no silent synchronization. Export/restore is explicit and validates provenance and session boundaries.
- A versioned service worker prepares the phone shell and static assets, then serves them from cache. It never caches API responses, pairing documents, credentials, or external source pages. It reports readiness only after preparing the full shell. Cached source text and stored explanations remain available without AI; free-form AI and URL extraction require the Mac service.
- The beta HTTPS server binds only to a private IPv4 or loopback address and checks the intended Host. A rate-limited, 30-minute pairing code installs a Secure, HttpOnly, SameSite=Strict device credential. Unpaired reads and mutations are blocked. A local certificate profile contains only a public root; preparation never alters system trust or firewall settings. Private keys and credentials stay in ignored, owner-protected files.
- Browser storage belongs to the origin and may be cleared or evicted. Request persistent storage without assuming it is granted, keep a stable `.local` hostname, and expose a Files/share backup plus confirmed validated restore. Installation and actual Safari/Home Screen behavior require a physical-device check.
- Playwright 1.63's WebKit offline emulation rejects service-worker navigation ([upstream report](https://github.com/microsoft/playwright/issues/42775)) and our file reads. For WebKit reload/restore validation, stop the real isolated HTTPS process and clear the emulation flag. Other offline actions still run with the flag enabled; Chromium checks use it throughout. This preserves meaningful disconnected testing without modifying app behavior to fit the runner.
- October 9 repository handoff: the owner reports the beta is functional. Keep local runtime data under a root-only `/data/` ignore rule so the attributed `src/data/seed.ts` ships with the app. Exclude generated Next.js declarations and generate route types before typechecking, following the installed Next.js guidance, so checks work from a fresh checkout.
